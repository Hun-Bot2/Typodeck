# 논문 ↔ ADR 매핑

> 기준: `docs/engineering/decisions/` ADR-0001~0019 (Accepted).
> 표기: [지지] 기존 ADR의 근거가 됨 / [확장] ADR을 넓히는 아이디어 / [갭] ADR에 없는데 필요함 / [주의] 오용 방지.
> 근거 수치는 각 정리 파일(01~07)의 §번호로 추적 가능.

## 1. 논문 → ADR (정방향)

### 01 PPTBench 2025 → IR 이중표현·게이트·구조 사전
- [지지] ADR-0002/0016 (Slide IR): 구조화 JSON+스크린샷 이중 입력 설계(§3.3.1)가 IR+렌더 이중 표현과 동형. 모달리티 분담 결과(JSON=조작, 시각=이해, §4.4)는 "IR 수치 검사 + 렌더 이미지 판단" 2채널 평가의 근거.
- [지지] ADR-0018 (Validation-Repair): 17개 원자 API 3원칙(Atomicity·Composability·Executability, §9.2) → Composition Engine 연산 설계 원칙. Modification "실행 후 JSON 완전일치"(§4.2) → 게이트 통과 기준.
- [지지] ADR-0006/0017 (Grammar Registry): API 템플릿 3종이 Generation +6~18점(§4.5.2) → 구조 사전(structural prior)의 실증. Registry는 이를 버전관리·조합 체계로 확장한 것으로 위치지을 수 있음.
- [지지] ADR-0007 (HTML≠증명): 렌더 기반 0–5 루브릭 + 인간 일치도 ρ 0.86–0.89(Table 4) → Visual Critic 신뢰성 검증 방법론 차용.
- [확장] §4.6 4종 레이아웃 실패(지배요소 오인식·비율 오판·겹침·중첩) → 게이트 오류 코드 체계 + "Valid→Good→Hierarchy" 단계론의 실증 근거.

### 02 UMSI → 위계 지표·게이트 루프의 원형
- [확장] ADR-0018: 응용 1 루프(목표 중요도→최적화 조정→모델 검증, §6.1) = 게이트 구조의 선례. 요소 마스크 평균 importance(§6.1–6.2) → IR 요소별 '예측 지각 중요도' 벡터 산출법 직접 차용.
- [갭] ADR-0016: emphasis 메타데이터가 IR 경계에서 drop됨. UMSI류 지각 모델과 비교할 '의도 위계'가 IR에 없으면 Hierarchy Agreement를 계산할 수 없음 → **IR에 의도 중요도 필드 보존 필요 (신규 ADR 후보 A)**.
- [지지] ADR-0012 (Typography-first): "상대 importance 보존 = 디자이너 의도 유지"(§6.2) → 타이포 수단(크기·대비·위치)으로 위계를 실현한다는 Typodeck 입장과 정합. 디자이너 인용("가장 중요한 것을 먼저 읽게") → 목표 정당화 인용.
- [주의] 슬라이드 미검증(광고·포스터·인포그래픽·웹·모바일 UI만). 16:9 분포 외 가능성, 텍스트 편향(§5.2), 정적 시청 기준(발표 맥락 부재). 인용 시 도메인 한정 명시.

### 03 SlideCoder → 재현 파이프라인·버전관리의 실증
- [지지] ADR-0001/0011 (편집가능 PPTX): RI-to-Slide 과제(원본 코드 없이 이미지+파일 쌍 비교) = Typodeck 재현 벤치마크와 구조적 동일.
- [지지] ADR-0017: OF-KB가 버전 불일치 오류 방지에 기여(§A.2) → Registry 버전관리의 당위성 실증.
- [지지] ADR-0018: Coder·Assembler 최대 3회 self-refinement = 게이트 패턴. 실행 실패 시 블록 폐기 규칙 → 게이트 설계 참조.
- [지지] ADR-0016: Describer 표준화 서술+스니펫 = 약한 중간표현. Slide IR이 명시적·버전관리라는 차별점 주장 가능.
- [확장] SCM(Pearson 0.873·ICC 0.726, §5.4) → 재현 벤치마크 난이도 라벨링 차용. 4종 지표(Global CLIP/SSIM + Local content/position + Execution + Overall) → Visual Critic 지표 체계 참조. 단 Overall의 실행률 지배(§6.2-7)는 분리 보고로 개선.
- [주의] 40.5점은 NL-입력 베이스라인 대비. 가중치·하이퍼파라미터 미공개로 전용 시 재보정 필요.

### 04 PPTAgent → 참조 기반·덱 구조·평가 차원의 근거
- [지지] ADR-0010 (447-ref 코퍼스): "참조를 고르고 편집하라"(§2.1) + 참조 기반 개선(design +40.9% 등, §4.5) → 참조 기반 접근의 정량 정당화.
- [지지] ADR-0003 (Purpose presets): 기능 유형 structural/content + 역할 라벨링(§2.2) ↔ 슬라이드 기능 유형. structural 제거 시 coherence 붕괴(§5.1) → 덱 구조 역할 모델링의 인과적 중요성 증거.
- [확장] ADR-0017: 스키마(무엇, 제거 시 성공률 95→78.8%, §5.1) + Grammar(어떻게) = 상호보완. "역할→시각 토큰" 매핑 이식으로 참조 품질 의존(한계 2) 완화 가능.
- [지지] ADR-0016: HTML 중간표현이 성공률 결정(CodeRender 제거 시 95→74.6%, §5.1) → "LLM 친화적 중간표현이 강건성에 결정적" 정량 근거.
- [확장] PPTEval Content·Design·Coherence 분리(§3) → Typodeck 평가 매핑(Content→충실도, Design→Good Layout, Coherence→Deck Rhythm) + 4번째 차원 Intended Visual Hierarchy 추가 = "PPTEval 상위호환" 프레이밍. 인간 일치도 Pearson 0.71·κ 0.59 → Critic 목표선("0.71 초과").
- [주의] self-correction이 실행 오류만 수리, 시각 결함(겹침) 잔존(한계 3) → "REPL 수리→렌더 수리" 진화 근거. 생성·평가 동일 모델(GPT-4o) → 심판-생성자 분리 반면교사.

### 05 LecSlides/SlideParser → 관계 모델링·그룹핑의 근거
- [확장] ADR-0002/0016: 텍스트 관계 모델링의 정량 가치(R-1 +5.9·METEOR +4.4, Table 5) → IR 관계 레이어(RPH류 pseudo-label) 도입 근거. lecture chunk(평균 3.2장) → IR 의미 단위 분할 규칙 참조.
- [지지] ADR-0018: 관계 일관성 검사(논리 관련 요소의 시각적 격리 여부) → 게이트 검사 항목 추가. QA 4유형(텍스트 추론 64%·시각 분석 18%·데이터 해석 14%·이진 4%) → 재현 벤치마크 루브릭 매핑.
- [확장] ADR-0006/0017: 공간+의미 이중 관계(DL-Cluster, 공간 제거 시 -3.9 vs 의미 제거 시 -0.8, Table 7) → 관계-스타일 규칙 버전관리(`same-cluster → spacing.compact` 등).
- [갭] 무방향 이진 관계만 제공 → Typodeck Grouping에 필요한 계층·순서·참조 방향 없음. **관계 유형화 확장이 선행돼야 함 (신규 ADR 후보 B)**. 이해용 hard mask(-∞)를 생성에 직이식 금지 → soft 제약으로 전환 필요.
- [주의] 강의 도메인 편향, 시각 요소 관계 공백(텍스트 간만), ROUGE/EM 지표는 레이아웃 품질과 무관. 라이선스 미기재(학습 편입 전 확인).

### 06 ColPali → 레퍼런스 검색 전용 (Critic 오용 금지)
- [확장] ADR-0010: 447개 레퍼런스 렌더링의 ColPali식 multi-vector 인덱스(447×257.5KB≈115MB, 풀링 시 ~38MB) → 디자인 사례 검색 Retrieval 단계. ViDoRe 쿼리 구축 공수(4명×3시간/100쿼리) → 평가셋 견적 참조.
- [주의] ADR-0018과 무관: LI 스코어는 쿼리-패치 근접도이지 품질이 아님(대비·정렬·위계는 목적함수에 없음, §4.2). **Visual Critic 점수로 해석 금지**. 허용 범위: 검색 디버깅·선택 근거·오매칭 분석. 최종 선정은 Visual Critic + Validation-Repair가 담당.
- [주의] 슬라이드 분포 미평가. 파일럿(인간 검증 쿼리 + nDCG/Recall) 후 도입. 38 후보 1차 필터 가능하나 관련도≠품질.

### 07 PPTBench 2026 → 게이트식 평가·텍스트 렌더 검사의 설계도
- [지지] ADR-0001/0011 + ADR-0018: Stage 0 산출물 유효성(파싱·단일 슬라이드·최소 3 네이티브 컴포넌트·래스터 금지, §2.3) → Valid PPTX 게이트 체크리스트로 이식.
- [지지] ADR-0018: 게이트식 점수(S=Gart·Gsem·Grt·세부합, "근본 실패를 세부 점수로 가릴 수 없게") = Valid→Good→Hierarchy 단계 목표와 동형. Stage 1 판정 항목(끝점·방향·분기·라벨) → 의미 보존 축 재사용.
- [갭] **텍스트 렌더 피팅 게이트 신설 (신규 ADR 후보 C)**: 잔여 감점 53%가 텍스트, 최대 항목 unexpected_wrap(§3.3). 원인 = OOXML 선언 vs 렌더러 줄바꿈 간극. Composition Engine 출력 뒤 렌더→오버플로·겹침·줄바꿈 검사를 게이트에 추가해야 함.
- [지지] 검사-재생성 루프: review 상관 r=0.881 vs revision r=0.255(§3.3) → "렌더 검사 빈도 우선" 설계의 경험적 지지. 단 인과 부인 → Typodeck 대조 실험 필요.
- [확장] 판정자 템플릿 차용: 3라운드 다수결·인간 블라인드 86.5%·반복성 96%·민감도·순위 안정성(§3.4) → Critic 신뢰도 보고 형식. 이슈 택소노미(High 3.0/Med 1.5/Low 0.5/Diagnostic 0 + 영향분율) → Registry 위반 심각도 체계 참조.
- [주의] 편집가능성 검증 얕음(최소 조건 수준). 과학 다이어그램 편향(500과제 전부). LibreOffice 고정(크로스 렌더러 검증 필요). 1위 CI가 0 포함(대역 서술).
