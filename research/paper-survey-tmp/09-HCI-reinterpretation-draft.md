# HCI 재해석 초안 (Typodeck 논문용)

> 테제: Typodeck은 슬라이드 연구의 3층 지형(Slide Understanding → Visual Importance → Layout Generation) 위에,
> **"의도된 의미 중요도와 지각된 시각 중요도의 일치(Visual Hierarchy Alignment)"** 를 핵심 설계 원리로 삼는다.
> 아래는 논문별 재해석 단락 초안 + HCI 고려 + 실험 제안. 수치 근거는 01~07 파일에서 추적.

## 1. 지형 규정 (관련 연구 장 구성안)

슬라이드 문제는 세 층으로 구분된다. 첫째 **Slide Understanding**(슬라이드에 무엇이 있고 각 요소의 의미·관계는 무엇인가).
둘째 **Visual Importance**(사람이 무엇을 먼저 보고 중요하게 인식하는가).
셋째 **Layout Generation**(의도한 위계가 전달되도록 어디에·얼마나 크게·어떤 관계로 배치할 것인가).
Typodeck의 핵심 문제는 둘째·셋째 층이며, 첫째 층은 이를 떠받치는 기반이다.

- 1층 기반: LecSlides-370K/SlideParser(05) — 텍스트 관계 모델링이 이해 성능을 결정(R-1 +5.9). PPTBench 2025(01) — 의미 이해와 시각-레이아웃 추론 사이의 격차를 실증.
- 2층 핵심: UMSI(02) — 지각된 중요도의 예측 가능성 + 상대 중요도 보존 원칙.
- 3층 핵심: SlideCoder(03)·PPTAgent(04)·PPTBench 2026(07) — 참조 기반·계층적·게이트식 생성/평가.
- 횡단(검색): ColPali(06) — 레퍼런스 검색 전용. 품질 평가와 엄격히 분리.

## 2. 논문별 재해석 (Typodeck 설계 결정의 근거로)

**PPTBench 2025(01) → "이해하는 모델이 배치하는 모델은 아니다".**
4,439개 샘플·4카테고리 평가에서 MLLM은 콘텐츠를 해석해도 일관된 공간 배치를 만들지 못했고(정렬 어긋남·겹침),
시각 단서와 JSON 레이아웃 구조의 결합에 실패했다. Typodeck은 이 격차를 정면으로 받아들여
(1) 구조(IR 수치 검사)와 지각(렌더 이미지 판단)을 분리한 2채널 평가(§4.4 모달리티 분담 결과에 근거),
(2) 버전관리 구조 사전(Grammar Registry; API 템플릿 +6~18점 효과의 체계화),
(3) 인간 일치도 ρ 0.85+ 검증 프로토콜(Table 4 방식)을 채택한다.

**UMSI(02) → "지각 위계는 예측 가능하고, 의도와의 일치가 곧 품질이다".**
Imp1k 1,000개·6개 디자인 유형에서 학습된 UMSI는 요소 마스크 평균 importance로 요소별 지각 중요도를 산출하고,
상대 중요도 보존 reflow·87% 중요도 조정 성공을 보였다. Typodeck은 이를 확장해
의도 위계(Slide IR의 구조적 단서)와 예측 위계(지각 모델 + IR 마스크 평균)의 순위 일치(Hierarchy Agreement, Spearman·Kendall)와
1순위 적중(Primary Emphasis Accuracy)을 핵심 지표로 정의한다.
전문 디자이너의 증언("가장 중요한 것을 먼저 읽게", §6.2)이 이 목표의 HCI 정당화다.
단 PPT 미검증 모델이므로 슬라이드 전이 검증이 선행 조건임을 명시한다.

**SlideCoder(03) → "재현은 분할-생성-조립이며, 분할이 최대 기여다".**
RI-to-Slide 과제에서 계층적 분할(CGSeg)+검색 증강(H-RAG)으로 Overall +40.5점·실행률 +38%p를 달성했고,
SCM 난이도 지표는 인간 판단과 r=0.873으로 정합했다. Typodeck 재현 파이프라인·벤치마크 난이도 티어·지표 체계의 선행 설계이며,
OF-KB의 버전 불일치 방지 효과는 Slide IR·Grammar Registry 버전관리의 실증적 당위성이다.

**PPTAgent(04) → "참조를 고르고 편집하라, 그리고 덱 전체를 평가하라".**
2단계 참조 기반 편집 접근은 design +40.9% 개선을 보였고, PPTEval은 Content·Design·Coherence를 분리 평가했다.
Typodeck은 참조 기반(447 코퍼스)·기능 유형(Purpose presets 대응)·스키마(무엇)+Grammar(어떻게) 보완·덱 단위 Rhythm 평가를 계승하고,
여기에 4번째 차원(Intended Visual Hierarchy)을 더해 "PPTEval 상위호환"으로 위치짓는다.
인간 일치도 Pearson 0.71·κ 0.59는 Visual Critic의 명시적 목표선("0.71 초과")이다.
반면 실행 오류만 수리한 self-correction과 생성·평가 동일 모델은 반면교사로 삼아 렌더 수리·심판 분리를 못 박는다.

**LecSlides/SlideParser(05) → "관계 없는 배치는 장식이 아니라 소음이다".**
370,078장 규모에서 텍스트 관계 모델링의 정량 가치(+5.9 R-1)와 공간 배치의 지배적 기여(공간 제거 -3.9 vs 의미 제거 -0.8)를 보였다.
Typodeck은 IR 관계 레이어·관계 일관성 게이트 검사·관계-스타일 규칙 버전관리로 이를 생성 관점에서 대칭화한다.
단 무방향 이진 관계의 한계를 인정하고 계층·순서·참조 방향의 유형화(B 후보)를 후속 과제로 둔다.

**ColPali(06) → "검색은 검색일 뿐, 심사가 아니다".**
ViDoRe에서 페이지 이미지 직접 임베딩+late interaction이 텍스트 파이프라인을 압도했으나,
그 점수는 쿼리-패치 근접도이지 디자인 품질이 아니다(대비·정렬·위계는 목적함수에 없음).
Typodeck은 ColPali류를 447 레퍼런스 검색 전용으로 한정하고(약 115MB→풀링 시 38MB 규모 추산),
품질 판단은 Visual Critic + Validation-Repair가 담당한다는 역할 분리를 선언한다. 유사도≠품질의 경계 설정 자체가 기여의 일부다.

**PPTBench 2026(07) → "유효한 파일과 좋은 재현은 별개이며, 검사가 편집보다 중요하다".**
500개 과학 다이어그램 재현에서 최고 77.34 vs 중앙값 24.38, 전 게이트 통과 31.7%.
잔여 감점의 53%는 텍스트 렌더 피팅(unexpected_wrap 최대) — OOXML 선언과 렌더러 결정의 간극이 원인이다.
검사 횟수-품질 상관(r=0.881)이 편집 횟수-품질 상관(r=0.255)을 압도한다.
Typodeck은 게이트식 평가(근본 실패 은폐 불가), 텍스트 렌더 피팅 게이트(C 후보), 검사 빈도 우선 루프,
판정 신뢰도 보고 템플릿(86.5% 인간 일치·96% 반복성)을 이 벤치마크에서 가져온다.

## 3. HCI 고려 (명시적 선언안)

1. **읽기 순서는 좌상단→우하단이 아니다.** 크기·색·위치·그룹화가 시선 우선순위를 바꾼다(MIT Comm Lab 가이드).
   Typodeck은 좌표 순서 강제가 아니라 의도-지각 위계 일치로 읽기 경험을 설계·검증한다.
2. **Attention ≠ Reading Order ≠ Comprehension.** 눈이 먼저 가는 요소가 먼저 읽히거나 잘 기억되는 것은 아니다.
   Typodeck 지표(Hierarchy Agreement 등)는 "정적 렌더 기준 지각 위계"로 범위를 한정하고, 이해도·발표 효과와 동일시하지 않는다.
3. **시청자 모델 vs 의도 모델의 이원 구조.** UMSI류 = 지각(perceived) 측면, Slide IR = 의도(intended) 측면.
   두 측면의 비교 자체가 기여이며, IR emphasis 필드 보존(A 후보 선행 조건)이 이를 가능케 한다.
4. **접근성 Reading Order는 별개 축.** 시각적 중요도와 스크린리더 객체 순서는 다를 수 있다(Microsoft 가이드).
   둘 다 검증 대상으로 두며, 한쪽의 통과를 다른 쪽의 통과로 주장하지 않는다.
5. **인간 판단이 최종 기준.** 모든 자동 지표는 인간 일치도(ρ·κ·blind 일치율)와 함께 보고하고,
   동일 모델의 자기 채점을 금지(심판-생성자 분리, D 후보)한다.

## 4. 검증 실험 제안 (A/B/C/D)

- 가설: 스크린샷 + 구조화 Layout JSON + 의도 중요도를 함께 주면(D), 텍스트만(A)·이미지만(B)·JSON만(C)보다 위계 오류 탐지가 낫다.
- 설계: 동일 덱·동일 오류 유형(의도적 축소·보조 확대·대비 반전) 30~50장. 인간 중요도 순위·오류 판단을 정답으로.
- 주의: D 우세는 미검증 가설. PPTBench 2025(01) §4.4에서 이미지+구조 결합의 어려움을 보고했으므로,
  구조 정보 제공 형식(원시 JSON vs 요약 서술 vs 관계 그래프) 자체를 실험 요인에 포함.
- 성공 기준 예시: D의 오류 탐지 F1이 B·C 대비 유의하게 높고, 인간 일치도 ρ 0.85+(01 Table 4 방식) 또는 0.71 초과(04 기준).

## 5. 서술 시 금지·주의 목록

- UMSI 수치의 슬라이드 직접 일반화 금지 ("슬라이드 미검증" 병기).
- ColPali 유사도를 품질 증거로 인용 금지.
- SlideCoder 40.5점 인용 시 비교 조건(NL 베이스라인 대비) 명시.
- PPTBench 2026 1위 "최고 모델" 확정 서술 금지 (CI가 0 포함 → 대역 서술).
- LecSlides ROUGE/EM을 레이아웃 품질과 혼동 금지.
- 모든 표 수치 인용 전 원 PDF 대조 (08-ADR-mapping.md §4 목록).
